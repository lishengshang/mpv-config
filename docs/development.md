## 分工方式

采用一个主 agent 加最多三个子 agent；数量按独立任务决定。

| 角色 | 负责内容 | 写入边界 |
| --- | --- | --- |
| 主 agent | 需求、接口、文件分配、集成、最终验证 | 根目录配置与跨模块文件 |
| 配置审查 agent | 键位、菜单、状态重置、选项联动 | 默认只读，给出具体修改建议 |
| 功能实现 agent | 一个独立 Lua 功能或 VS 预设 | 明确分配的脚本与选项文件 |
| 验证 agent | 复现、日志分析、回归检查 | 默认只读；测试工具须单独分配 |

例如“优化 AI 字幕并排查快捷键”：一个 agent 实现 `scripts/sub-fastwhisper.lua` 与对应选项，一个只读审查字幕键位和状态重置，一个核对后端命令与失败场景，主 agent 修改 `input.conf` 并集成验收。依赖实现完成的回归验证在集成后执行，不能把有依赖的步骤当成并行任务。

共享工作区适合不同文件的修改与并行审查。多个 agent 必须修改相同文件时，使用独立 worktree；集成后仍需测试最终组合。先确认 worktree 的 mpv 配置路径、被忽略的机器配置和外部 VS 运行时，避免测试到主工作区而误认为验证了自己的修改。

## 可直接使用的指令

```text
按本仓库 AGENTS.md 用多 agent 完成以下需求：<需求与预期行为>。
主 agent 先划分文件所有权，然后启动最多三个独立子任务。
配置审查 agent 只读检查键位、菜单和状态联动；
实现 agent 只修改明确分配的功能脚本与选项；
验证 agent 先整理复现方法和失败场景，集成后检查最终结果。
根目录配置统一由主 agent 修改。
等待所有子任务结束，集成后运行必要检查，报告未验证项。
不要提交或发布。
```

每个子任务至少提供以下信息：

```text
目标：<具体的前后行为>
允许写入：<文件列表>
只读参考：<相关配置、脚本和文档>
接口约定：<消息名、选项名、键位、预设名>
验收：<命令或操作、成功证据、失败场景>
返回：修改文件、结果、验证证据、未解决事项
```

## 验收顺序

1. 记录初始工作区状态，确定需求范围与文件所有权。
2. 检查实现、配置、快捷键、菜单和文档是否一致。
3. 运行 `git diff --check`；检查新文件与最终 diff。
4. 用对应运行环境验证修改的行为，包括失败和重置路径。
5. 集成后复查跨模块行为，明确区分静态通过、运行通过与未验证。

纯文档修改只检查内容、链接和编码。GPU 测试记录设备、驱动、后端、模型、媒体规格及结果；性能优化需在同一条件下比较修改前后。
